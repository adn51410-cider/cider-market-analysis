# シードル市場分析ダッシュボード - 要件定義書

## 要件定義の作成原則
- **「あったらいいな」は絶対に作らない**
- **拡張可能性のための余分な要素は一切追加しない**
- **将来の「もしかして」のための準備は禁止**
- **今、ここで必要な最小限の要素のみ**

## 1. プロジェクト概要

### 1.1 成果目標
シードル市場とアルコール市場全体（特にワイン・日本酒）を多角的に比較分析し、市場規模・成長率・価格帯・消費者属性・販売チャネル・季節性の6つの視点から、シードルの位置づけと成長機会を可視化。データに基づいた説得力のある販売戦略を立案して、印刷可能な資料形式で会社に効果的に提案できる状態を実現する。

### 1.2 成功指標

#### 定量的指標
- **6視点の比較分析**: 市場規模・成長率・価格帯・消費者属性・販売チャネル・季節性すべてを可視化
- **酒類カバレッジ**: 5種類以上の酒類（ワイン・日本酒・ビール・焼酎・RTD等）との比較データを整備
- **戦略立案サイクル**: 月1回以上、データに基づく戦略案を作成できる
- **提案の採用率**: 会社への提案のうち50%以上が承認・実行される
- **資料作成時間**: 提案資料の作成時間を50%削減（エクスポート機能活用）

#### 定性的指標
- **市場全体の俯瞰**: アルコール市場全体におけるシードルの位置づけを立体的に把握できる
- **ワイン・日本酒との差別化**: 特に重要な競合との比較から、具体的な訴求ポイントが明確になる
- **成長機会の発見**: 他の酒類が強いセグメントから、シードルの参入余地や差別化ポイントを見つけられる
- **説得力のあるストーリー**: 「なぜ今シードルなのか」を市場データで語れる
- **戦略的思考の習慣化**: 勘や経験だけでなく、多角的なデータで考える習慣がつく

## 2. システム全体像

### 2.1 主要機能一覧
- **市場データ可視化**: シードルと他の酒類を6つの視点で比較分析
- **インタラクティブフィルター**: 期間選択、酒類カテゴリー選択による動的なグラフ更新
- **データ自動取得**: e-Stat API経由で政府統計データを自動取得
- **レポート出力**: グラフを含むPDF形式の提案資料を自動生成

### 2.2 ユーザーロールと権限
- **ゲスト**: すべての機能にアクセス可能（認証不要のMVP構成）

### 2.3 認証・認可要件
- **認証方式**: 不要（究極のMVP - 2ページ構成）
- **セキュリティレベル**: 公開情報のみ扱うため最小限
- **管理機能**: 不要

## 3. ページ詳細仕様

### 3.1 P-001: 市場分析ダッシュボード

#### ルート
`/`

#### 目的
シードルと他の酒類市場を6つの視点で比較分析し、戦略立案に必要な洞察を得る

#### 主要機能
- 6つの分析視点の切り替え（市場規模・成長率・価格帯・消費者属性・販売チャネル・季節性）
- 酒類カテゴリーの比較グラフ表示（ワイン・日本酒を強調、他の酒類も表示）
- インタラクティブなフィルター（期間選択、酒類選択）
- データの自動更新（e-Stat API経由）
- CSV補完インポート機能（必要に応じて）

#### 必要な操作

| 操作種別 | 操作内容 | 必要な入力 | 期待される出力 |
|---------|---------|-----------|---------------|
| 取得 | 市場データの取得 | 期間（開始年月～終了年月）、酒類カテゴリー | 選択期間・カテゴリーの市場データ（JSON） |
| 取得 | 分析視点の切り替え | 視点種別（市場規模/成長率/価格帯/消費者属性/販売チャネル/季節性） | 選択視点に応じたグラフデータ |
| 作成 | CSVインポート（補完） | CSVファイル | データベースへの保存完了 |
| 更新 | データ再取得 | なし（ボタンクリック） | 最新データの取得・表示更新 |

#### 処理フロー
1. ページ読み込み時、e-Stat APIから最新データを自動取得
2. デフォルト表示：直近12ヶ月の市場規模比較（ワイン・日本酒・シードル・ビール・焼酎）
3. ユーザーが分析視点を選択（ドロップダウン）
4. ユーザーが期間・酒類カテゴリーを選択（フィルター）
5. 選択に応じてグラフをリアルタイム更新
6. 「レポート出力」ボタンでP-002に遷移

#### データ構造（概念）

```yaml
MarketData:
  識別子: データID（自動生成）
  基本情報:
    - 酒類カテゴリー（必須）: ワイン/日本酒/シードル/ビール/焼酎/RTD
    - 年月（必須）: YYYY-MM形式
    - データソース（必須）: e-Stat/国税庁/手動
  市場データ:
    - 市場規模（任意）: 金額（円）、数量（リットル）
    - 成長率（任意）: 前年同月比（%）
    - 平均価格（任意）: 円/リットル
    - 消費者属性（任意）: 年齢層別購入金額
    - 販売チャネル（任意）: チャネル別シェア（%）
    - 季節指数（任意）: 月別消費傾向
  メタ情報:
    - 作成日時
    - 更新日時
  関連:
    - なし（単独エンティティ）
```

### 3.2 P-002: レポート出力

#### ルート
`/report`

#### 目的
分析結果を印刷可能な資料形式で出力し、会社への提案資料を作成する

#### 主要機能
- PDF形式でのレポート生成
- 選択した分析視点・期間のグラフを自動挿入
- カスタマイズ可能なレポートタイトル・コメント
- 複数グラフの一括出力
- 印刷最適化レイアウト

#### 必要な操作

| 操作種別 | 操作内容 | 必要な入力 | 期待される出力 |
|---------|---------|-----------|---------------|
| 取得 | レポートプレビュー表示 | P-001で選択した分析設定 | レポートプレビュー（HTML） |
| 作成 | PDFレポート生成 | レポートタイトル、コメント（任意） | PDFファイルのダウンロード |
| 更新 | レポート設定変更 | タイトル、含めるグラフの選択 | プレビューの更新 |

#### 処理フロー
1. P-001からの遷移時、選択されたグラフ設定を引き継ぐ
2. レポートタイトル・コメント入力フォーム表示
3. 含めるグラフを選択（チェックボックス）
4. プレビュー表示
5. 「PDF出力」ボタンクリック
6. グラフを画像化（html2canvas）
7. @react-pdf/rendererでPDF生成
8. ファイルダウンロード

#### レポートデザイン仕様

**基本方針**: 簡潔でわかりやすいレポート

**デザイン原則**:
- **1ページ1グラフの原則**: 各ページに1つのグラフのみ配置、情報の詰め込みを避ける
- **大きく見せる**: グラフはA4の70%を使用
- **シンプルな構成**: 余計な装飾なし

**レポート構成**:
```
① 表紙
  - レポートタイトル（18pt太字、メイリオ）
  - 作成日
  - 対象期間

② グラフページ（選択したグラフ数だけ繰り返し）
  - グラフタイトル（18pt太字、メイリオ）
  - グラフ（A4の70%）
  - 簡潔な説明（12pt、メイリオ、2-3行）

③ まとめページ（任意）
  - コメント欄（ユーザー入力）
```

**フォント・スタイル**:
- **フォント**: メイリオ
- **サイズ**: タイトル18pt、本文12pt
- **色**: グラフはカラー、文字は黒のみ
- **余白**: 上下左右20mm

**グラフページレイアウト**:
```
┌──────────────────────────────┐
│                              │ ← 上余白20mm
│  【グラフタイトル】          │ ← 18pt太字メイリオ
│                              │
│  ┌────────────────────────┐  │
│  │                        │  │
│  │    グラフ（大）        │  │ ← A4の70%
│  │                        │  │
│  └────────────────────────┘  │
│                              │
│  説明: この期間において...   │ ← 12ptメイリオ、2-3行
│                              │
│                              │ ← 下余白20mm
└──────────────────────────────┘
```

**カスタマイズ可能項目**:
- **必須入力**: レポートタイトル、対象期間
- **任意入力**: コメント（まとめページ）
- **選択**: 含めるグラフ（チェックボックス）

#### データ構造（概念）

```yaml
ReportConfig:
  識別子: 一時ID（セッション内のみ）
  基本情報:
    - レポートタイトル（必須）: 文字列
    - コメント（任意）: テキストエリア
    - 作成日時（必須）: 自動設定
  グラフ設定:
    - 含めるグラフ（必須）: グラフID配列
    - 期間設定（必須）: 開始年月～終了年月
    - 酒類選択（必須）: カテゴリー配列
  メタ情報:
    - 作成日時
  関連:
    - MarketData（参照のみ）
```

## 4. データ設計概要

### 4.1 主要エンティティ

```yaml
MarketData:
  概要: アルコール市場の統計データ（市場規模・成長率・価格帯等）
  主要属性:
    - 識別属性: データID、酒類カテゴリー、年月
    - 市場データ: 市場規模、成長率、平均価格、消費者属性、販売チャネル、季節指数
    - メタデータ: データソース、作成日時、更新日時
  関連:
    - なし（単独エンティティ）

ApiCache:
  概要: e-Stat APIから取得したデータのキャッシュ
  主要属性:
    - 識別属性: キャッシュID、APIエンドポイント、パラメータハッシュ
    - キャッシュデータ: レスポンスJSON、有効期限
    - メタデータ: 取得日時
  関連:
    - なし（パフォーマンス最適化用）
```

### 4.2 エンティティ関係図

```
MarketData (単独)
  - 酒類カテゴリー × 年月の組み合わせで一意

ApiCache (単独)
  - e-Stat APIレスポンスのキャッシュ
  - 5分間有効
```

### 4.3 バリデーションルール

```yaml
酒類カテゴリー:
  - ルール: 許可リスト（ワイン/日本酒/シードル/ビール/焼酎/RTD）のいずれか
  - 理由: データの一貫性確保

年月:
  - ルール: YYYY-MM形式、2000-01以降
  - 理由: e-Stat APIのデータ範囲に準拠

市場規模（金額）:
  - ルール: 0以上の数値
  - 理由: 負の値は無効

成長率:
  - ルール: -100以上の数値（%）
  - 理由: 前年比-100%未満は市場消滅を意味し無効
```

## 5. 制約事項

### 外部API制限
- **e-Stat API**: リクエスト制限あり（詳細は登録時に確認、通常は1秒あたり数リクエスト程度）
- **対策**: PostgreSQL（Neon）でキャッシュ、5分間有効期限設定

### 技術的制約
- **シードル単独データ**: 日本の税法上「果実酒」に分類されるため、単独統計データは限定的。ワイン・果実酒カテゴリーとして扱う
- **ブラウザ制限**: PDF生成はクライアントサイドで実行、大量データ（50グラフ以上）の場合はメモリ不足の可能性
- **データ更新頻度**: e-Stat APIの更新頻度に依存（月次が基本）

## 5.1 セキュリティ要件

### 基本方針
本プロジェクトは **CVSS 3.1（Common Vulnerability Scoring System）** に準拠したセキュリティ要件を満たすこと。

CVSS 3.1の評価観点:
- **機密性（Confidentiality）**: 不正アクセス防止、データ暗号化
- **完全性（Integrity）**: データ改ざん防止、入力検証
- **可用性（Availability）**: DoS対策、冗長化

詳細な診断と改善は、Phase 11（本番運用診断）で @本番運用診断オーケストレーター が実施します。

## 6. 複合API処理（バックエンド内部処理）

### 複合処理-001: 市場データ自動取得・キャッシュ

**トリガー**: ダッシュボードページ読み込み、または「データ更新」ボタンクリック

**フロントエンドAPI**: GET /api/market-data?category={酒類}&from={開始年月}&to={終了年月}

**バックエンド内部処理**:
1. **キャッシュ確認** - PostgreSQLでキャッシュ存在チェック（パラメータハッシュで検索）
2. **キャッシュ有効性判定** - 取得日時から5分以内ならキャッシュ返却、期限切れなら次へ
3. **e-Stat API呼び出し** - 家計調査データAPI（統計表ID指定）から該当期間のデータ取得
4. **データ変換** - e-StatレスポンスJSON → MarketDataエンティティ形式に変換
5. **キャッシュ保存** - PostgreSQLにキャッシュとして保存（有効期限5分）
6. **レスポンス返却** - フロントエンドにJSONで返却

**結果**: 酒類カテゴリー別・期間別の市場データ（JSON）

**外部サービス依存**: e-Stat API、PostgreSQL（Neon）

### 複合処理-002: PDFレポート生成

**トリガー**: レポート出力ページで「PDF出力」ボタンクリック

**フロントエンドAPI**: クライアントサイド処理（サーバー不要）

**クライアント内部処理**:
1. **グラフ画像化** - html2canvasでRechartsコンポーネントをCanvasに変換
2. **画像データ取得** - CanvasからBase64エンコードされた画像データ取得
3. **PDFドキュメント生成** - @react-pdf/rendererでPDFドキュメント作成
4. **画像埋め込み** - Base64画像をPDFに埋め込み
5. **ファイルダウンロード** - Blobオブジェクトとしてダウンロードトリガー

**結果**: PDFファイルのローカル保存

**外部サービス依存**: なし（クライアントサイド完結）

## 7. 技術スタック

### フロントエンド
- **フレームワーク**: React 18
- **言語**: TypeScript 5
- **UIライブラリ**: MUI v6
- **状態管理**: Zustand
- **データフェッチ**: TanStack Query
- **ルーティング**: React Router v6
- **ビルドツール**: Vite 5

### データ可視化・レポート
- **チャートライブラリ**: Recharts
- **PDF生成**: @react-pdf/renderer + html2canvas
- **データ処理**: react-papaparse（CSV処理）

### バックエンド
- **フレームワーク**: Next.js 15（APIルート機能）
- **言語**: TypeScript 5

### データベース
- **メインDB**: PostgreSQL（Neon）
  - サーバーレス、管理不要
  - 無料枠：512MB RAM、10GB ストレージ
  - 用途：e-Stat APIキャッシュ、分析設定保存

### インフラ
- **開発・検証フェーズ**: Vercel
  - 無料枠、自動デプロイ、プレビューURL生成
- **本番フェーズ（会社運用）**: Google Cloud Run
  - GCP統合、サーバーレス、自動スケーリング
  - 無料枠：月200万リクエスト

### 選定理由
1. **React + TypeScript**: Blue Lampの自動化エージェント群が最適化、型安全性による品質保証
2. **MUI v6**: 統一されたデザインシステム、レスポンシブ対応
3. **Recharts**: React専用で実装容易、6つの分析視点すべてに対応
4. **Zustand + TanStack Query**: 軽量で高速、e-Stat APIのキャッシュ・同期を自動管理
5. **Next.js**: APIルート機能でe-Stat API連携を実装、Vercel/Cloud Run両対応
6. **PostgreSQL (Neon)**: サーバーレスで運用コスト0円、APIキャッシュでAPI制限対策
7. **段階的デプロイ**: 開発時Vercel（無料）→ 本番時Cloud Run（会社GCP統合）
